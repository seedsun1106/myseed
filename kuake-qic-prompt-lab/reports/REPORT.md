# KUAKE-QIC Prompt 调优实验 · 完整归因报告

> 本报告对应封版配置 `prompts/v2.txt` + `data/holdout.csv`。所有数字均取自 `results/` 与 `reports/f1_macro_report.csv`，构建本仓库期间**未调用任何模型 API、未重跑评测、未改动任何结果 CSV 数值**。

## 1. 实验设计：四集合、预注册、验收线

### 1.1 四集合
| 集合 | 规模 | 角色 |
|---|---|---|
| A. Dev 全量 | 150（`DT-` 90 + `DB-` 60） | 唯一允许用于 Prompt 迭代的集合 |
| B. Dev / typical | 90 | 典型样本分层，检查常规意图是否退步 |
| C. Dev / boundary | 60 | 边界样本分层，检查规则是否误伤长尾 |
| D. Holdout（黄金留出集） | 50（`HO-001~050`） | 调优全程封存，只在期末考解封一次 |

另有一个**外部校验源**：KUAKE-QIC 官方 `dev.txt`（1955 行），只用于核对 200 条样本的官方标签（150/150 与 50/50 全部一致），不参与任何调优决策。四集合与外部源之间：Holdout 与 Dev 的 id 重叠 0、query 精确重叠 0、query strip 后重叠 0。

### 1.2 单变量控制
每一轮只改两处：`PROMPT_V0` 常量与结果输出文件名。以下全部保持不变：`model=glm-5.3-flash`、`temperature=0.1`、`reasoning_effort=low`（经 `extra_body` 透传）、11 类中文→英文映射、用户消息取 `input` 原文、JSON 解析与 `FORMAT_ERROR` 规则、0.6s 调用间隔、失败重试 2 次（间隔 3s）、每 10 条进度、`--limit`、按已有 id 断点续跑、`utf-8-sig` 六列结果落盘。密钥仅由 `os.environ.get("ZHIPU_API_KEY")` 读取，脚本内无明文密钥。每轮使用独立结果文件名，避免断点续跑复用上一版结果造成假对照。

### 1.3 考前预注册（看到留出集结果之前冻结）
1. **封版配置**：V2 Prompt（13 行类别定义 + 8 条判定示例，833 字符 / 22 行）；封版后不得再依据 Dev 分数挑选版本。
2. **评分口径**：accuracy + 固定 11 类 one-vs-rest 的 P/R/F1，分母为 0 记 0，macro-F1 为 11 类 F1 算术平均（含 F1=0 的类，不加权不剔除）。
3. **验收线**：`|Dev 准确率 − Holdout 准确率| ≤ 5pct`。
4. **噪声清单**：考前依据类别定义逐行审计，预注册 Dev 侧约 12% 可疑金标，并冻结 Holdout 侧 8 条疑似噪声 query（`HO-003/004/005/006/037/046/048/050`）。
5. **零重叠**：id / query 精确 / query strip 三种口径均为 0 才允许开考。

### 1.4 验收线
以 Dev 74.67% 为基准，Holdout 落在 `[69.67%, 79.67%]` 即判定泛化通过；低于下界视为过拟合调优集，高于上界需复查数据泄漏。

## 2. 迭代过程：五版与逐轮归因

| 版本 | Prompt 干预 | Dev 准确率 | typical | boundary | 相对上一版 |
|---|---|---|---|---|---|
| V0 | 仅枚举 11 类 code | 35.33%（53/150） | 36.67% | 33.33% | — |
| V1 | +11 类判定要点（13 行定义） | 70.00%（105/150） | 68.89% | 71.67% | **+34.67pct** |
| V2 | +8 条判定示例 | **74.67%（112/150）** | 74.44% | 75.00% | +4.67pct |
| V3 | +2 条示例 + 2 条边界规则 | 74.00%（111/150） | 75.56% | 71.67% | −0.67pct |
| V3.1 | 退回 V2 正文，只留 1 条示例 + 1 条规则行 | 70.67%（106/150） | 70.00% | 71.67% | −3.33pct |

五版 Prompt 全文见 `prompts/v0.txt ~ v3_1.txt`（逐字节取自历次写入快照）；逐轮结果见 `results/`；翻转清单见 `reports/flips_*.csv`。

### 2.1 V0 → V1：给判定依据，收益最大
V0 只列了 11 个 code，模型把大量 query 塞进 `advice`（40 次）、`cause`（21 次）、`effect`（18 次），`other` 只预测 1 次而实际有 24 条；`result` 8 条全错、`other` 24 条只中 1 条。加上类别定义后，`result` 0→75%、`metric_explain` 20→90%、`method` 27.3→81.8%、`effect`/`advice` →100%，唯一退步是 `price` 100→83.3%（少 1 条）。**结论：分类任务的第一生产力是"每类怎么判"，而不是"有哪些类"。**

### 2.2 V1 → V2：few-shot 拉回兜底类，收益递减
8 条判定示例把"陈述句 / 闲聊"往 `other` 拉了一把（`other` 12.5→29.2%，3/24→7/24），`diagnosis` 50→66.7%、`disease_express` 80→90%、`attention` 75→83.3%；代价是 `metric_explain` 90→80%、`effect` 100→90.9%（各少 1 条）。翻转清单：**错变对 11 条、对变错 4 条、净 +7**。相对 V1 的 +34.67pct，few-shot 只带来 +4.67pct，干预收益明显递减。此版封版。

### 2.3 V2 → V3：一条规则纯赚，一条规则误伤
V3 在 V2 末尾追加 2 条示例并新增「边界规则」段。拆开看：

- **疾病属性规则纯赚**：`disease_express` 90→100%（`DT-050 三尖瓣下移畸形有没有遗传?` 由 `cause` 转对），`metric_explain` 80→90%（`DT-079` 回到 `metric_explain`），`DT-022`、`DT-089` 也转对。
- **diagnosis / other 规则误伤**：「提到自身症状并求判断即 diagnosis」把 `DB-059 像怀孕吗？` 从 `other` 拉成 `diagnosis`、`DT-010 查出颈椎…怎么治疗` 从 `method` 拉成 `diagnosis`，另有 `DT-062`、`DT-090`、`DB-044` 转错。`other` 29.2→25.0%，boundary 75.00→71.67%，typical 反而 74.44→75.56%。翻转清单：**错变对 4 条、对变错 5 条、净 −1**。即同一段规则内部正负相抵，total 只掉 1 条。

### 2.4 V3 → V3.1：删掉"有害"规则反而更差，Prompt 是系统
V3.1 退回 V2 正文，只保留被认为"纯赚"的那条疾病属性规则（外加 1 条疾病属性示例），预期应 ≥V3，实测 **74.00%→70.67%（−3.33pct）**：`other` 的预测次数从 V2 的 **9 次塌到 2 次**，`other` 准确率 29.2→8.3%（24 条只中 2 条）；`result` 75→62.5%、`attention` 83.3→75%、`method` 81.8→78.8% 各退 1 条；改善只有 `disease_express` 90→100%、`metric_explain` 80→90%。模型把"遗传 / 传染 / 癌变归 disease_express"泛化成了"凡是不确定就往具体类里塞"，把兜底判断挤没了。**单条规则的边际收益依赖它所在的上下文；V3 里两条规则互相支撑，抽走一条，另一条就变成噪声源。**

### 2.5 两条被毙方案（未进入任何版本）
- **多意图裁决**：`DT-003 请教腹部痉挛、手脚麻木的原因和治疗方法` 金标 `method`，而 `DB-011 / DB-012` 同为"原因 + 治疗"的复合意图却标 `cause`。同一意图模式两种金标，任何"原因优先 / 治疗优先"的裁决规则都会与另一半样本冲突，也会直接打脸 V2 的 `method` 示例，故毙掉。
- **副作用切分**：`DT-075` 标 `result`、`DB-036` 标 `effect`，而类别定义表又把"用药 / 孕期禁忌"写进 `attention` —— `result` / `effect` / `attention` 三处定义互相矛盾。在金标本身不自洽时加 Prompt 规则只会把噪声固化，故毙掉。

### 2.6 同一偏差的指纹：cause 过预测
Dev 上 `cause` 的精确率只有 **0.4375**（模型预测 16 次、实际仅 7 条），召回却是 1.0 —— 典型过预测。Holdout 上同一指纹复现：`HO-007 / HO-008 / HO-039` **3 条 `diagnosis` 被判成 `cause`**（"呼吸有气味是哪里的问题""跟预防针有关系吗""突然便秘是怎么回事"），`cause` 精确率 0.4。这不是随机波动，而是 V2 Prompt 对"怎么回事 / 哪里的问题 / 有没有关系"这类溯因句式的系统性偏向，且跨集合稳定出现。

## 3. 期末考：封版 V2，留出集一次解封

- 数据：`data/holdout.csv`，50 条 `HO-001~050`，与 Dev 零重叠，50/50 标签与官方 `dev.txt` 一致。
- 配置：`prompts/v2.txt` + `data/holdout.csv` + `results_holdout.csv`，模型与解析参数一字未改。
- 结果：**72.00%（36/50），macro-F1 71.07%，FORMAT_ERROR 0**，无重试、无报错。`typical/boundary` 显示 N/A，因为留出集不带 category 分层。
- 验收：`|74.67% − 72.00%| = 2.67pct ≤ 5pct` → **泛化验收通过**，V2 没有明显过拟合调优集。
- 14 条错题（`results/holdout_errors.csv`）按考前冻结清单归因：**预注册 8/8 命中**，8 条为金标噪声（模型答案比金标更贴定义），6 条为模型真实能力错误；**剔除标注噪声后净准确率 (36+8)/50 = 88%**。
- 逐类强弱与 Dev 一致：`other` 与 `diagnosis` 双弱（Holdout `other` F1=0、`diagnosis` F1=0.25），`advice` / `metric_explain` / `price` 双满分，`method` 11/12、`result`/`effect` 全对。**泛化不是分数不变，而是强弱指纹复现。**

## 4. 金标噪声与天花板

三条独立证据互证金标存在可测量噪声：

1. **Dev 逐行审计**：按类别定义表复核，约 **10–13%** 的样本存在"金标与定义冲突 / 复合意图被强行单标"。
2. **考前预注册**：冻结的 Dev 侧可疑样本约占 **12%**，Holdout 侧 8 条；开考后 Holdout 预注册 **8/8 命中**。
3. **成绩震荡带**：V2 74.67% → V3 74.00% → V3.1 70.67%，逐轮净变化只有 ±1 条 / −6 条，且翻转清单显示"错变对"与"对变错"同时大量出现（V1→V2 为 11/4，V2→V3 为 4/5），说明剩余错误里有相当部分不是 Prompt 能解决的。

三者共同指向**合理上限 85–90%**：在金标不清洗的前提下，继续堆规则只会移动错误分布而非消灭错误。留出集按预注册清单归因后的 **88% 净准确率**正好落在这一区间上沿。因此本实验主动在 V2 封版，把资源从"再调 Prompt"转向"先修金标 / 双人复核"。

## 5. 方法论教训

1. **单变量 + 独立结果文件**：只改 Prompt 与输出名，才能让 5 个版本构成可比对照；断点续跑若复用同一文件名会直接毁掉实验。
2. **留出集必须封存且预注册**：验收线、噪声清单、评分口径都必须在看到留出集结果之前冻结，否则"调参直到通过"没有统计意义。
3. **看 macro-F1 而不只看 accuracy**：Dev 上 `cause` 精确率 0.4375 的过预测，在 74.67% 的总分里几乎看不出来，只有逐类 P/R/F1 才暴露。
4. **Prompt 是系统，不是规则清单**：V3.1 证明删除"有害"规则可能让整体更差；规则之间存在支撑与抵消关系，任何增删都要整版重测。
5. **泛化 = 指纹复现**：逐类强弱分布跨集合一致，比单一总分持平更能说明模型行为稳定。
6. **先量噪声，再定天花板**：当剩余错误主要由金标噪声构成时，正确动作是停手并修数据，而不是继续调模型。

## 6. 局限

- **样本量小**：Holdout 仅 50 条，二项 95% 置信区间约 **±13pct**，2.67pct 的 Dev/Holdout 差距远小于区间宽度，只能说明"未见过拟合"，不能证明等价；Dev 150 条的分层（90/60）同样偏小。
- **金标未双人复核**：噪声判定由单人依类别定义审计得出，未做双人独立标注与一致性系数（如 Cohen's kappa），10–13% / 12% / 88% 均为估计值而非审计结论。
- **单次采样**：单一模型（`glm-5.3-flash`）、`temperature=0.1`、`reasoning_effort=low`、每题一次调用，未做多次采样估计输出方差，也未测其他模型 / 温度。
- **数据口径**：中文 query 含口语、重复句、尾随符号（如 `...`、`_`）与错别字，未做任何清洗；官方 `dev.txt` 标签本身亦可能带噪。
- **分层缺失**：留出集不含 `category`，故无 typical/boundary 分层结果，无法检验边界样本在留出集上的泛化。
- **归因主观性**：8 条噪声归类基于"模型答案更贴类别定义"这一判据，属人工归因；若金标复核结论不同，88% 净准确率需相应修订。
